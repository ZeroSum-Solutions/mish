# Independent critique — Grok 4.7, 2026-09-22

- **Reviewer:** Grok 4.7 via SuperGrok subscription, document-only, not an author or owner of this design system.
- **Date:** 2026-09-22
- **Version reviewed:** neutral-product@0.1.0
- **Packet source commit:** fbf0ae525d (`feat(design-systems): add Neutral Product golden exemplar as candidate`)
- **Verdict:** FAIL

This review was a document-only packet review (no live repository tools):
the reviewer read the shipped DESIGN.md, tokens.css, components.html, and
the four specimen pages as supplied text, without running the gate or a
browser. Findings 1–3 were independently verified against the checked-in
source before any fix landed; findings 4–10 are recorded here verbatim as
received. Items acted on this pass are noted; the rest are carried forward
as open items in `docs/plans/2026-09-22-design-system-wave-0.md`.

## Findings

1. **BLOCK — `preview/specimen-website.html`.** At 600–1023px (including the
   required 768px), `.site-nav` was `display: none` and `.menu-toggle` was
   still `display: none` (it turned on only below 599px), so there was no
   way to reach Product / How it works / Pricing / Questions in that band.
   **Verified.** **Fixed:** the disclosure toggle now shows for the whole
   `max-width: 1023px` range.

2. **BLOCK — `preview/specimen-app.html`, `components.html`.** The app
   sidebar's "Open navigation" button had no panel, `aria-controls`, or
   `aria-expanded`, and could not be opened. `components.html`'s pattern
   demo used a different phone pattern (a horizontal-scrolling `.sidenav`),
   so the system had no single collapse pattern for this nav shape.
   **Verified.** **Fixed:** both now open the sidebar/sidenav as a
   disclosure panel with a backdrop, `aria-controls`, `aria-expanded`,
   Escape-to-close, and focus moved into the panel on open.

3. **BLOCK — `components.html`, `preview/specimen-app.html`.** The global
   `:focus-visible` rule drew focus with `box-shadow: var(--focus-ring)`.
   `.nav-link[aria-current="page"]` and `.sidenav a[aria-current="page"]`
   set their own `box-shadow` at higher specificity, which silently
   canceled the focus ring on the current nav item — the focused current
   item looked identical to the unfocused one. Gate contrast ratios for
   `--accent` on `--surface-warm` (6.60:1 light, 6.94:1 dark) were fine;
   the ring color was never the problem, and DSP-12 never measured
   `--surface-warm` so it never noticed the override. **Verified.**
   **Fixed:** focus is now drawn with `outline` / `outline-offset` across
   every specimen and `components.html`, a different property that no
   `box-shadow` rule can cancel; `box-shadow` is reserved for the
   selected-item inset bar. DSP-12 now also checks the ring color against
   `--surface-warm` in both modes.

4. **WARN — `preview/specimen-app.html`.** At 360px the responsive table
   drops the checkbox, owner, and activity columns via `display: none`,
   but the footer still reports "1 selected" with no visible selection
   control; `nth-child` selectors position the remaining columns against
   hidden siblings. Not fixed this pass — carried to the open-items list.

5. **WARN — `DESIGN.md`, `components.html`.** Tinted status/badge
   backgrounds use `color-mix()` at 92%/72%/60% depending on context, while
   DESIGN.md states one `transparent 88%` recipe; the resulting composited
   text contrast is outside DSP-11's token-pair math (it evaluates raw
   tokens, not `color-mix()` output). Estimated composited contrast still
   clears 4.5:1 in every case checked, but the gate cannot currently prove
   it. Not fixed this pass — carried to the open-items list.

6. **WARN — `tokens.css`.** In dark mode, `--accent` (8.18:1 on `--bg`) and
   `--muted` (8.16:1 on `--bg`) are close enough in weight that links and
   the current-item bar read like secondary gray text. Not fixed this
   pass — carried to the open-items list.

7. **WARN — `DESIGN.md`.** Several documented rules disagree with the
   specimens or each other: the tablet breakpoint is named both 768px and
   1023px; dark-mode hover is said to darken but `--accent-hover` is
   lighter than `--accent` in dark mode; imagery frames are said to use
   `--elev-ring` but use `--elev-raised`; `--text-4xl` is described as
   "marketing hero only" but appears on the deck slide and social post; the
   documented 12/6/1-column grid does not match any specimen; the
   "no mixed filled/outlined icons" rule is broken by every header (a
   filled logo mark next to line icons). Not fixed this pass — carried to
   the open-items list.

8. **WARN — `components.html`.** The system's own stated hit target is
   40px, but the switch (36×20px hit area is the control alone) and
   `.btn-sm` (32px tall) fall short of it, even though both clear the
   WCAG 2.5.8 floor and DSP-07's 24px minimum. Not fixed this pass —
   carried to the open-items list.

9. **WARN — `docs/design-systems/QUALITY-STANDARD.md`.** DSP-11 does not
   see `color-mix()`-composited text; DSP-12 only checked `--bg`/`--surface`
   (see finding 3 — DSP-12 now also checks `--surface-warm`, but the
   general "a check should see CSS composited values" gap remains);
   DSP-06/DSP-16 make a 768px fixture optional even though this system's
   own sidebar rule is a 768px behavior; DSP-04 does not check that
   documented breakpoints/hover direction/specimens agree with each other;
   nothing checks that `components.html`'s CSS matches each specimen's
   copy of the same rules; nothing measures target size; DSP-18's "≥7 H2
   sections" is redundant with DSP-04's topic check. Not fixed this pass —
   carried to the open-items list.

10. **NIT — `components.html`, specimens.** `kbd` used a hardcoded
    `border-radius: 4px` and `.avatar` used a hardcoded `font-size: 10px`,
    both untokenized. **Fixed:** `kbd` now uses `var(--radius-sm)` and
    `.avatar` now uses `var(--text-xs)`, across `components.html` and all
    four specimens (`.avatar-32` already used a token). The document
    fixture's chart `.bar` (hardcoded `border-radius: 3px`) was also moved
    to `var(--radius-sm)`. The link `border-radius: 2px` used to shape the
    focus outline around inline text was left as-is: it is the same value
    in every file, intentional (there is no token sized for a text-link
    outline corner), and not itself an inconsistency.

## Disposition

Findings 1–3 (BLOCK) and 10 (NIT) are fixed on this branch. Findings 4–9
(WARN) are real and are carried forward as open items for the next wave —
see "Open items from the 2026-09-22 critique" in
`docs/plans/2026-09-22-design-system-wave-0.md`. This critique's verdict is
recorded as `fail` in `promotion.json`; per the promotion gate, a failed
critique does not block `candidate` status, and this system's status stays
`candidate`. A `promoted` status still requires at least one independent
critique of this exact version with verdict `pass`, which this critique is
not.
