# Inactive exclusive placement foundation

The movement primitives below remain inactive: no route, automatic build, packaged loader or public activation. Bootstrap ownership, owned migrations, recovery, the project registry and run lifetime are integrated internally as described in [RUNTIME.md](RUNTIME.md). The adoption executor ([ADOPTION.md](ADOPTION.md)) is the only movement caller; it needs an explicitly provisioned helper and otherwise stays closed. The TypeScript build function requires explicit source and output paths. Generated helper binaries remain outside tracked source. Intel is compile-only; execution is admitted only on the measured arm64 Darwin 25.5.0 runtime with a writable local case-insensitive APFS volume and valid, set exclusive-rename capability.

The driver opens both parent directories with Darwin `O_NOFOLLOW_ANY`, records lossless device/inode/volume identities, and holds only those descriptors. Each movement requires a new executor-supplied durable-intent callback and invocation ID. Final named parents are re-resolved after that callback and after movement. The helper refuses unrelated inherited descriptors and validates its version, names, descriptors, capabilities, parents and source observations before one `renameatx_np(RENAME_EXCL | RENAME_NOFOLLOW_ANY)` call. Destination occupancy includes same-entry case and Unicode aliases. Symlink, special, dataless, immutable/append-only and hard-linked file sources are declined.

An `observed-move` requires the helper's source-absence and expected-target observations, exited-child evidence and matching final named parents. It still requires executor-owned content verification. Raw syscall success is not a placement receipt, coherent tree snapshot, metadata backup or expected-inode compare-and-swap. Parent/source observations and helper digest checks are advisory against concurrent same-user edits. Build SHA is provenance, not signed packaging or atomic executable authentication.

Lost, malformed or excessive output, abnormal exit, synchronous spawn failure and helper timeout return `unknown-result` with possible mutation. The driver waits for child close before returning an exited-child witness. A null child on an unexpected driver exception supplies no exit proof and keeps recovery unresolved. The timeout initiates termination rather than promising an absolute completion deadline. A failed post-move observation preserves all objects and supplies a typed conflict. No path is removed, restored or automatically retried. A future executor may prepare a separate inverse move only from a still-supported retained observation and with a new journaled intent. Recreated names, unsupported classes or ambiguous ownership require partial-location/manual recovery.

Daemon ownership is a separate in-process boundary. This movement helper receives only its two parent descriptors in stdio positions 3 and 4, never an owner lock descriptor. The future executor owns recovery/liveness registration, journal/flush ordering, independent preimages, root/authority/coordinator gates and retention policy. Retention must be explicitly supplied, same-volume and outside build/style scans. Daemon-managed paths must follow the root [data directory contract](../../../../../AGENTS.md#daemon-data-directory-contract).

Focused tests live in the [placement tests](../../../tests/workbench/placement/). They retain owned fixture objects for evidence. `OD_PLACEMENT_TEST_EVIDENCE` selects an existing evidence parent; absent that setting the OS temporary directory is used. The native cases skip unqualified hosts. The owner-descriptor case additionally requires `OD_PLACEMENT_OWNER_PROBE` to name the separately qualified ownership probe; it reuses that probe and does not duplicate flock. It proves descriptor exclusion and continued contention through a successful move and a successful move whose reply is lost. Signing, packaging, Intel execution, older OS support, journals, crash recovery and route activation remain unverified.

The caller must close every prepared movement. Close waits for pending execution and attempts both owned descriptor closes without replacing its typed movement outcome with a cleanup exception. An intent callback must not await that same movement’s close: close waits for the callback and would deadlock.

## Inactive native daemon owner

`owner-build.ts` builds an explicit N-API bundle from explicit source, output and pinned Node24.16 header paths through Xcode clang. It records source, header, compiler/SDK and binary evidence; it neither installs dependencies nor selects a runtime output. `owner-binding.ts` loads only an explicitly selected SHA-matching development bundle. SHA is build provenance; signed materialization remains a packaging gate. Intel builds are compile-only.

The owner acquires `flock(LOCK_EX | LOCK_NB)` in the calling daemon process on one fixed persistent reserved inode, `.daemon-placement-owner.lock`, under the explicitly supplied canonical data root. It requires main-thread Node24.16, arm64 Darwin25.5.0, a private UID-owned mode0700 no-symlink root on writable local APFS with a valid, set flock capability and volume UUID. The owner inode must be UID-owned, regular, mode0600, single-link, same-device and free of unsupported flags. Allow/unknown ACL entries and unreadable ACLs decline qualification; deny-only ACLs remain intact. A newly created reserved inode receives mode0600 even under a restrictive umask; existing inode permissions remain unchanged. It preserves existing bytes and declines unsafe objects without changing permissions or links.

The binding exposes only canonical root, synchronous inspection and explicit close. Raw descriptors, duplicate/unlock/forward APIs and spawned ownership are absent. Its native descriptors are CLOEXEC. It keeps contexts through garbage collection until explicit close or environment shutdown. TypeScript callbacks retain the actual native method receiver when F3 consumes them.

Inspection distinguishes a held original lock from current qualification. It verifies held descriptor identities and freshly resolves the named root and owner inode; replacement, unsafe metadata, descriptor loss and failed capability checks permanently taint that instance. Root or inode replacement may leave `held:true, qualified:false`. Uncertain inspection or close never certifies release. Explicit close checks identities, preserves reused foreign descriptors and the persistent inode, and can be retried after a refused close. Acquire-failure cleanup uncertainty remains tracked through environment shutdown and returns close-uncertain. Inspection and native failure results include errno diagnostics. Arbitrary same-process raw descriptor manipulation remains outside this trusted interface's guarantee.

This supplies native attestation to the trusted F3 binding only. The caller must still supply its independent previous-incarnation recovery reader. Acquisition, GC, process exit and zero local counters do not prove that earlier children drained. Bootstrap ordering, all writer/run permits, durable launch/journal/drain recovery, imported/shared physical-root ownership, signing/loading/Intel/otherOS qualification and public activation remain gates. Data-root selection follows the root data directory contract linked above; this module never discovers or guesses it.

## Run cancellation and accepted final work

The inactive `write-coordinator.ts` refuses new unticketed project and data-root publication as soon as `cancelRun` marks a run draining, before `finishRun`. A callback accepted before cancellation, including one waiting for physical-root resolution, remains counted until it settles. Valid publication and cleanup drain tickets still authorize final writes within the original start, scope and recovery constraints. An unstarted cancelled run can clean allocation state only through a reserved cleanup ticket and a data-root write.

Cancellation retains the run registration and physical project gates. Whole-data-root placement stays blocked until `finishRun` and all accepted callbacks and tickets drain; independent project mutations can proceed. Ticket confirmation must still attest actual drainage. No runtime caller is activated by this foundation.
